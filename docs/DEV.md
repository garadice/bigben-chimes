## Hard constraints (same charter as london-boom)

- **Zero build step** — plain HTML/CSS/JS. No framework, no npm runtime.
- **Zero runtime network** — no fetch/CDN/fonts. Everything local, SW-cached.
- **Asset gate** — only separately-licensed open material; every asset needs
  a LICENSES.md entry. Never extract anything from a store-bought app.
- **Cache rule:** bump `CACHE` in sw.js whenever any cached file changes
  (deploy cache-bust). v1.1.0 ships with `bigben-chimes-v1.1.0`.
- Kid-safe audio: no sudden loud spikes; cut edges are de-clicked.
- **SW + media gotcha (verified 2026-11-08):** Chrome loads audio/images with
  byte-range requests; answering those with a cached full 200 stalls the
  media element forever (readyState 0, no error). sw.js therefore slices the
  cached body into a real 206 for any Range request — keep that when editing
  the fetch handler.

## Source and evidence (all numbers below are measured, not assumed)

Source: `Westminster chimes (1 January 1945).wav`, Wikimedia Commons — the
Radio Oranje New Year broadcast (PD-EU-audio). 72.4 s, 48 kHz stereo PCM.
A working copy sits outside the repo; re-derive anything from the Commons
original if needed.

### 1. Hour-strike interval — measured 3.99 s

Method: DC-blocked one-pole high-pass (>≈1.1 kHz) envelope + rise-after-dip
transient detection, then pitch verification per onset (normalized
autocorrelation, 140–470 Hz search). Exactly **12 strike onsets**, all
dominantly **E3** (r = 0.73–0.81 — i.e. midnight, 12 strikes):

```
21.50  25.44  29.48  33.52  37.51  41.57  45.60  49.61  53.53  57.42  61.40  65.39
intervals: 3.94 4.04 4.04 3.99 4.06 4.03 4.01 3.92 3.89 3.98 3.99  -> mean 3.990 s
```

Cross-checks (published):

- UK Parliament (parliament.uk, "Big Ben chimes for New Year's Eve", 2020):
  the temporary electric strike mechanism "replicates … dropping it on the
  bell **every 4.5 seconds**, the same speed as the Great Clock's original
  mechanism".
- westminsterchime.com (field recordings at the tower): "The strokes come
  **about four seconds** apart."

Our measurement (3.99 s) matches the field observation and sits ~11 % below
Parliament's mechanism spec. The 1945 recording's pitches also read a few
percent sharp of concert (E3 strike ≈ 174 Hz vs 164.8 Hz nominal), which
suggests the archival transfer runs slightly fast — on the real tower the
interval is likely 4.2–4.5 s. **Decision:** ship the measured 3.99 s — the
bong sample itself lives on this recording's timeline, so self-consistency
wins. Constant: `chime.js BONG_GAP = 3.99`.

### 2. Melody structure of the source (0–22 s) and the slicing map

The chime content runs 0.34–21.05 s; the strike train starts at 21.2 s.
Pitch analysis (Goertzel band power at the five bell pitches, ±6 % scan for
wow/flutter; the bell PRIME partial dominates, harmonics reinforce) mapped
the confidently-classified stretches:

```
~0.34–2.7   tail of a previous phrase (mush — heavy 1945 reverb)
C4 ≈ 3.45    G#4 E4 F#4 B3min   (B3-minim run 7.80–8.24 = C4 note 4)
C5 ≈ 9.65    B3 F#4 G#4 E4min   (B3 run 9.48–10.80 = C5 note 1;
                                 G#4 run 12.72–13.96 = C5 note 3;
                                 E4 dominance from 14.20 = C5 note 4,
                                 the tonic minim, ringing out to 21.05)
strikes from 21.2, 12 × 3.99 s
```

This is changes 4+5 of the pre-midnight hour change (Wikipedia: the hour
plays changes 2, 3, 4, 5; the source's opening simply catches the chime
already in progress, and changes 2+3 are NOT present in this file — v1's
"full 16-note sequence" description of `melody.m4a` was wrong about content,
not about audio; corrected in LICENSES.md).

**Why assemble, not slice, changes 1–3:** the four bell positions inside a
documented change are canonically fixed (change 5 = B3 F#4 G#4 E4), so single
bell slices give every pitch needed to build the missing phrases at the
recording's own rhythm. The five changes per Wikipedia:

```
1: G#4 F#4 E4 B3   2: E4 G#4 F#4 B3   3: E4 F#4 G#4 E4
4: G#4 E4 F#4 B3   5: B3 F#4 G#4 E4
:15 = 1 · :30 = 2+3 · :45 = 4+5+1 · :00 = 2+3+4+5 + strikes
:30/:00 end on the tonic E4; :15/:45 end on the dominant B3.
```

**Slice windows** (each opens ~0.15 s before its note's attack, ends before
the next attack; chosen on the strongest pitch-run evidence):

| asset | src range | why this window |
|---|---|---|
| n-gs4 | 12.72–14.02 | strongest G#4-dominant run (10/10 windows classify G#4) |
| n-e4  | 14.05–15.45 | tonic minim onset, E4-dominant (10/10) |
| n-b3  | 9.55–11.05  | longest B3 run (11/12) |
| n-fs4 | 2.30–3.45   | **weakest slice** — the F#4 bell is barely separable from the 1945 reverb anywhere in the file (best window scores F#4 in only 4/10 windows, B3-leaning tail); scanned 10 candidate windows, this was the best. Documented, not hidden. |
| q45a  | 3.30–15.50  | contiguous recorded changes 4+5 (structure verified: mush → B3min → B3-long → G#4 → E4-tonic) |
| bong  | 41.47–44.90 | one strike + decay. v1's bong (src 41.60–45.70) accidentally contained the FIRST 0.10 s of the NEXT strike's attack at its tail — fixed here (transient count inside the cut: exactly 1) |

Per-slice verification (same Goertzel classifier, post-cut): n-gs4 G#4 10/10,
n-e4 E4 10/10, n-b3 B3 11/12, n-fs4 F#4 4/10 + B3 2/10 (see above), bong 1
attack @0.09 s.

**Rhythm constants** (measured on the recording, same speed caveat as the
strike interval): crotchet slot `NOTE_STEP = 1.5 s` (C5 onsets 9.65 → 14.15
over 3 steps), minim→next-phrase `MINIM_STEP = 1.7 s` (phrase span
C4@3.45 → C5@9.65 = 6.2 = 3×1.5 + 1.7).

### 3. How the quarters are built (chime.js `quarterEvents`)

```
:15  4 note slices at 0/1.5/3.0/4.5                 (change 1)          ~6.0 s
:30  8 note slices, minim slot after note 4         (changes 2+3)      ~12.1 s
:45  q45a (recorded 4+5, 12.20 s) + change 1 slices (4+5+1)            ~18.2 s
:00  changes 2+3 assembled + melody.m4a at 12.4 s   (2+3+4+5 = 16 notes)
     + first strike at melody end + 0.6 s, then N × 3.99 s
BONGY: bongs only, 3.99 s apart, N = (hour % 12) || 12
```

The 0.6 s melody→strike pause is a deliberate kid-app compromise: the
broadcast itself has 0.19 s there, the real tower ~25 s (Wikipedia, "sounds
25 seconds before the main bell tolls"). Constant: `STRIKE_PAUSE = 0.6`.

Deviation from the canonical :00 (honest, documented): the recorded C4+C5 is
byte-original audio; changes 2+3 are re-assembled from bell slices. There was
no way to slice changes 2+3 from the source (they are not in the file). The
assembled phrases use real recorded bells at the recording's own rhythm.

## Quarter scheduler semantics (chime.js `createQuarterScheduler`)

- Injected `now()` (tests) — the app passes `Date.now() + offset`.
- One fire per quarter mark (key `YYYY-MM-DDTHH:MM` of the mark itself);
  the play callback receives the quarter index and builds its timeline.
- Grace window **90 s**: a mark more than 90 s stale (Android froze the tab)
  is consumed silently — no blast from the past; the next fresh mark fires.
- Plain `setEnabled(true)` mid-mark fires the current mark at once
  (deliberate: toggling on gives instant feedback if inside grace).
- `setEnabledQuiet(true)` arms without firing — used at boot (app.js) to
  restore a persisted ON toggle (no mid-mark blast) and in tests.

## Layout note: photo `cover`, not `contain`

v1.1 tried `object-fit: contain` ("show every photo pixel"). Visual QA
flagged it: at phone aspect the photo letterboxes with hard navy bands at
top and bottom, which read as broken. Final: `cover` — at 390×844 it trims
only ~8 % of the photo's width (open sky/foliage at the edges) while the
tower stays complete, spire to base, with nothing covering its middle
(the v1.1 spec's actual complaint was the v1 full-width button bars).

## Kid-play improvements shipped in v1.1

1. **STOP square (✋, solid red)** — cancels every pending timeline timer,
   pauses all players, hides the counter; the auto-quarter TOGGLE is not
   touched (stopping sound ≠ switching the mode off).
2. **Big bong counter** — a huge serif numeral flashes centre-screen on each
   strike (the timeline carries 1-based `n`); teaches counting to 12.
3. **Tower sway** — the photo rocks ±0.7° from its base on every bong
   (CSS keyframes, transform-origin at the ground; disabled under
   `prefers-reduced-motion`).
4. **Vibration pulse** — `navigator.vibrate(140)` per bong (Android tactile;
   silently skipped where unsupported).

No network, no libraries, emoji + CSS animation only.

## Audio unlock (Android Chrome)

First `pointerdown`/`touchend` anywhere plays every player (melody, q45a,
4 note slices, 4 bongs) muted and pauses it; afterwards unmuted `play()` is
allowed. Buttons also call `unlock()` before playing. No autoplay on load.

## Testing

- Logic: `node tools/chime_test.js` (124 checks) — bong counts, quarter
  keys, the four per-quarter timelines (file order + measured rhythm),
  canonical ending-pitch rule (:15/:45 → B3, :30/:00 → E4), strike counts
  and 3.99 s spacing, scheduler grace/rollover semantics.
- Asset verification (done at cut time, see section 2): per-slice Goertzel
  pitch-class + bong transient count.
- Browser (manual/agent sweep): serve `python3 -m http.server`, check zero
  console errors, tap every column button, spy `__BBC__.stats()` /
  `playQuarter()`, shift the clock with `__BBC__.setClockOffset(ms)` to hit
  quarter marks, verify SW + manifest + icons resolve, then stop the server
  and reload to prove offline works.
- `window.__BBC__` exposes playEvents/cancelAll/players/scheduler/playQuarter
  for tests.
